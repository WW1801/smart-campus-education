# 校园教务系统需求文档

## 1. 系统概述

校园教务系统是一个为学校提供全方位教学管理功能的信息系统，旨在提高教学管理效率，优化教学资源配置，为师生提供便捷的教学管理服务。系统涵盖学生管理、教师管理、课程管理、成绩管理、排课管理等核心功能，实现教学管理的数字化、自动化和智能化。

### 1.1 系统目标

- 提高教学管理效率，减少人工操作
- 优化教学资源配置，合理安排课程和教师
- 为师生提供便捷的信息查询和管理功能
- 实现教学数据的集中管理和分析
- 支持学校教学管理的规范化和标准化

### 1.2 系统范围

本系统适用于各类大中专院校，支持多校区、多院系、多专业的教学管理。系统主要覆盖以下范围：

- 学生信息管理
- 教师信息管理
- 课程信息管理
- 成绩管理
- 排课管理
- 教学计划管理
- 考勤管理
- 毕业管理

## 2. 功能需求

| 角色 | 描述 |
|------|------|
| 系统管理员 | 负责系统配置、用户管理、权限分配等系统级功能 |

## 3. 非功能需求

### 3.1 性能需求

- **响应时间**：系统页面加载时间不超过3秒，数据查询响应时间不超过2秒
- **并发处理**：支持至少1000个并发用户同时访问系统
- **数据处理**：能够处理至少10万学生、1万教师、5万课程的数据量
- **系统稳定性**：系统连续运行时间不低于30天，无故障

### 3.2 安全需求

- **身份认证**：采用基于角色的访问控制（RBAC），确保用户只能访问授权的功能
- **数据加密**：敏感数据（如密码）采用加密存储
- **访问控制**：对系统功能和数据进行细粒度的权限控制
- **审计日志**：记录系统操作日志，便于安全审计和问题追溯
- **防SQL注入**：系统应采取措施防止SQL注入攻击
- **防XSS攻击**：系统应采取措施防止跨站脚本攻击

### 3.3 可靠性需求

- **数据备份**：定期自动备份系统数据，确保数据安全
- **故障恢复**：系统出现故障时，能够在30分钟内恢复正常运行
- **数据一致性**：确保系统数据的一致性和完整性
- **错误处理**：系统应具备完善的错误处理机制，确保系统稳定运行

### 3.4 可用性需求

- **系统可用性**：系统工作时间的可用性应达到99.9%
- **界面友好**：系统界面应简洁、直观，易于操作
- **响应式设计**：系统应支持不同设备（PC、平板、手机）的访问
- **帮助文档**：提供详细的系统使用帮助文档

### 3.5 可扩展性需求

- **模块化设计**：系统采用模块化设计，便于功能扩展和维护
- **接口标准化**：系统应提供标准化的API接口，便于与其他系统集成
- **数据结构可扩展**：系统数据结构应具备良好的扩展性，以适应未来业务需求的变化

#### 4.1.9 成绩（Grade）

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| grade_id | VARCHAR(20) | PRIMARY KEY | 成绩ID |
| student_id | VARCHAR(20) | NOT NULL, FOREIGN KEY | 学号 |
| course_id | VARCHAR(20) | NOT NULL, FOREIGN KEY | 课程ID |
| semester_id | VARCHAR(20) | NOT NULL, FOREIGN KEY | 学期ID |
| teacher_id | VARCHAR(20) | NOT NULL, FOREIGN KEY | 教师ID |
| usual_score | DECIMAL(5,2) | NULL | 平时成绩（0~100） |
| exam_score | DECIMAL(5,2) | NULL | 考试成绩（0~100） |
| total_score | DECIMAL(5,2) | NOT NULL | 总成绩（0~100） |
| status | ENUM('pending', 'approved', 'rejected') | NOT NULL | 成绩状态：pending-待审核，approved-审核通过，rejected-审核驳回 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

> **成绩审核流程**：教师录入成绩 → 状态为 pending → 院系管理员审核通过 → 状态为 approved（系统自动根据 total_score 判定及格/不及格）→ 院系管理员审核驳回 → 状态为 rejected → 教师修改后重新提交 → 状态为 pending。

> **成绩计算规则**：必修课 total_score = usual_score × 30% + exam_score × 70%；专业选修课 total_score = usual_score × 40% + exam_score × 60%；公共选修课 total_score = usual_score × 50% + exam_score × 50%。权重可在系统配置中按课程维度覆盖。考试成绩缺考时 total_score = 0。

## 5. 业务流程

### 5.1 学生注册流程

1. 新生提交注册信息
2. 院系管理员审核注册信息
3. 系统生成学号和学生档案
4. 学生完成缴费
5. 系统激活学生账号

### 5.2 课程选报流程

1. 教务处发布选课通知
2. 学生登录系统选择课程
3. 系统验证课程可选性（如先修课程、时间冲突等）
4. 学生确认选课
5. 系统生成学生个人课表

### 5.3 排课流程

1. 教务处设置学期和排课规则
2. 院系提交课程和教师需求
3. 系统自动生成初始课表
4. 教务处和院系审核课表
5. 系统发布最终课表

### 5.4 成绩管理流程

1. 课程结束后，教师录入学生成绩
2. 院系管理员审核成绩
3. 系统计算学生绩点和排名
4. 学生查询个人成绩
5. 系统生成成绩报表

### 5.5 毕业审核流程

1. 学生提交毕业申请
2. 院系审核学生的学分和成绩
3. 系统生成毕业资格审核报告
4. 教务处最终审核
5. 系统发放毕业证书和学位证书

### 5.6 成绩审核流程

1. 课程结束后，教师录入学生成绩（状态为 pending）
2. 系统按课程类型自动计算总成绩（必修30%+70%，专业选修40%+60%，公共选修50%+50%）
3. 院系管理员审核成绩（通过则状态变为 approved，系统自动判定及格/不及格；驳回则状态变为 rejected）
4. 驳回的成绩由教师修改后重新提交
5. 已 approved 的成绩不可直接修改，需走成绩更正流程（教务处审批）
6. 系统根据已审核成绩计算学生绩点（GPA）

### 5.7 选课流程

1. 教务处发布选课通知，设定选课时间窗口
2. 学生登录系统查看可选课程（根据教学计划和先修课程过滤）
3. 学生选择课程安排（schedule_id），系统校验：
   - 选课时间是否在窗口内
   - 是否满足先修课程要求
   - 选课容量是否已满（current_students < max_students）
   - 是否与已选课程时间冲突
4. 校验通过后，系统创建选课记录（status=selected），同时 course_schedule.current_students +1
5. 学生可在退选期内退选（status=dropped），current_students -1
6. 选课结束后，系统生成学生个人课表

## 5B. 核心业务规则

### 5B.1 成绩计算规则

| 规则项 | 规则内容 |
|-------|---------|
| 必修课总成绩 | total_score = usual_score × 30% + exam_score × 70% |
| 专业选修课总成绩 | total_score = usual_score × 40% + exam_score × 60% |
| 公共选修课总成绩 | total_score = usual_score × 50% + exam_score × 50% |
| 及格标准 | total_score ≥ 60 为及格，< 60 为不及格 |
| 缺考处理 | exam_score 为 NULL 时，total_score = 0，自动判定不及格 |
| 绩点计算 | score ≥ 60 时：绩点 = (score - 50) / 10；score < 60 时：绩点 = 0 |
| GPA计算 | GPA = Σ(单科绩点 × 课程学分) / Σ课程学分 |
| 权重覆盖 | 权重可在系统配置中按课程维度覆盖，以上为默认值 |

### 5B.2 排课冲突规则

| 冲突维度 | 判定条件 | 优先级 |
|---------|---------|-------|
| 教师时间冲突 | 同一学期 + 同一教师 + 同一天 + 时间段重叠 | P0（最高，不可违反） |
| 教室容量冲突 | 教室容量 < 上课人数 | P1 |
| 教室时间冲突 | 同一学期 + 同一教室 + 同一天 + 时间段重叠 | P2（可换教室解决） |
| 班级时间冲突 | 同一学期 + 同一班级 + 同一天 + 时间段重叠 | P3（最低，可调时段） |

> 时间段重叠判定：[start1, end1] 与 [start2, end2] 重叠条件为 start1 <= end2 AND start2 <= end1。

### 5B.3 学籍流转规则

| 当前状态 | 目标状态 | 流转条件 | 审批角色 |
|---------|---------|---------|---------|
| active | suspended | 学生提交休学申请 + 院系审核通过 | 院系管理员 |
| suspended | active | 学生提交复学申请 + 院系审核通过 + 缴清欠费 | 院系管理员 |
| suspended | dropped | 休学期满未复学（超过2年）或主动申请退学 | 教务处管理员 |
| active | dropped | 学生申请退学 + 院系初审 + 教务处终审 | 教务处管理员 |
| active | graduated | 满足毕业条件 + 院系审核 + 教务处审批 | 教务处管理员 |

> 禁止流转：graduated → 任何状态（终态，不可逆）；dropped → active（需重新注册，生成新学号）。

> 退学劝退条件：累计不及格课程学分 ≥ 20学分（可配置）。
